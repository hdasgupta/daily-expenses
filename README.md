# Rehabilitation Center Expense Tracker

Full-stack expense tracker built with React + Vite, Node.js + Express, Neon PostgreSQL, S3-compatible proof storage, and a scheduled dashboard PDF email workflow.

## Project structure

- `backend/` layered Express API with controllers, services, models, middleware, utilities, and SQL scripts.
- `backend/scripts/sql/` contains every SQL statement used by the backend. No SQL is embedded in controllers, services, models, or DB bootstrap code.
- `frontend/` React/Vite UI with responsive cards, navigation drawer, theme toggle, reusable loader, toast, modal, password, and pagination components.
- `frontend/vercel.json` proxies `/api/*` to the Render backend and serves the Vite SPA.
- `render.yaml` describes the Render backend service and environment variables.

## Roles and permissions

Admin receives every application permission. Editor receives `add-expense`. Manager receives `add-expense`, `report`, and `dashboard`.

The only business data seeded automatically is the required admin account. Categories, items, units, and survivors are not sample-seeded.

## Admin bootstrap

Default admin email: `wbffmh@gmail.com`.

Set `ADMIN_PASSWORD` in the backend environment. The application does not overwrite an existing admin account because the seed operation uses an email conflict guard.

## Environment files

Backend supports `.env.local`, `.env.development`, and `.env.production`. Frontend has matching environment files. Production secrets should be entered in the Render dashboard rather than committed to Git.

Required production backend values include:

- `DATABASE_URL`
- `JWT_SECRET`
- `AWS_ENDPOINT_URL_S3`
- `AWS_ACCESS_KEY_ID`
- `AWS_SECRET_ACCESS_KEY`
- `AWS_REGION`
- `AWS_S3_BUCKET`
- `EMAIL_API_URL`
- `EMAIL_API_KEY`

The supplied Neon S3 endpoint is already configured in the environment templates, while access credentials remain placeholders.

## Proof storage

PDF proofs are uploaded directly to the S3-compatible Neon Object Storage endpoint. PNG/JPEG images are converted to PDF in the backend before upload. The database stores the proof object key and optional bulk-import Google Docs / contract URL metadata.

## Expense shares

Every expense requires at least one survivor share. A share can be fixed, average, or remaining. The backend resolves shares to exact currency amounts and validates that the resolved amounts equal total cost. When a report/dashboard is survivor-oriented, the survivor share amount is shown instead of repeating the full expense total.

## Bulk expense CSV

The predefined template uses these fields:

`date,category,item,other_item,quantity,unit,price,total_cost,expense_type,shares,comment,added_by,added_on,proof_google_docs_id,contract_download_url`

`date` is `yyyy,mm,dd`. Quoting the date cell is supported, and the importer also accepts an unquoted first three date cells and merges them.

`shares` uses comma-separated values inside a quoted CSV cell:

`Survivor Name|600,Another Survivor|25%,Last Survivor|~`

Amounts and percentages are resolved to database currency shares. `~` receives the remaining amount. Unknown survivor names are skipped individually.

## Password rules

Passwords require at least eight characters, one uppercase letter, one lowercase letter, one digit, one special character, and no spaces. The UI displays live tick/cross validation and includes show/hide buttons and confirmation matching.

## Email trigger

Password-reset OTPs and dashboard PDFs are sent using an HTTP POST to `EMAIL_API_URL`. Configure the endpoint to accept the JSON payload generated by `mailService.js`.

## Formatting
